## Issues Found & Fixed

### 1. Discord-bot agent dead after Sep 7th chaos

**Symptom:** Bot not responding in Discord.  
**Root cause:** Agent was killed manually 4 times on Sep 7th. `sessionManager.restart()` cannot revive a completely dead agent — it requires the agent to be in the registry. Only `spawnAgent()` (called at daemon startup) can do that.  
**Fix:** Container restart. Daemon called `spawnAgent()` on startup, trust dialog was handled correctly (see #2 below), agent came back as PID 181.

---

### 2. Trust-folder dialog regression — `fix/trust-dialog-respawn` branch (commit 75691bf)

**Symptom:** Agent would silently die on spawn after CLI 2.1.263 upgrade.  
**Root cause:** CLI 2.1.263 changed the trust-folder dialog default selection from "Yes, I trust this folder" to "No, exit". A bare `Enter` on respawn now accepted the *No* option and killed the agent.  
**Fix:** Added `answeredTrustPrompt` guard in `src/bus/session-agent-process.ts`. If the "Yes" row isn't already selected (detected via `❯` prefix in PTY buffer), sends `Down+Enter` to navigate to it first. One-shot guard prevents double-answering.  
**Status:** Committed, branch `fix/trust-dialog-respawn`. Needs version bumps + PR before merge.

---

### 3. Claude Code version pin overwritten

**Symptom:** Running `claude --version` showed a newer version than the validated 2.1.141.  
**Root cause:** A previous Claude session ran an explicit `npm install --global @anthropic-ai/claude-code` without pinning the version. The `autoUpdates: false` in `.claude.json` only blocks the auto-updater, not explicit npm installs.  
**Fix:** Added PreToolUse Bash hook at `/root/.claude/hooks/claude-version-pin-guard.sh`. Blocks any `npm install --global @anthropic-ai/claude-code` that doesn't pin to `2.1.141`. Returns exit code 2 (blocked) for unguarded installs; exit 0 for the pinned version or unrelated commands.

---

### 4. Bash tool needed approval on every command

**Symptom:** Every Bash tool call prompted for approval in the Claude Code session.  
**Root cause:** `"Bash"` was not in the `permissions.allow` list in `/root/.claude/settings.json`.  
**Fix:** Added `"Bash"` to the allow list. Hooks still gate specific commands (version-pin guard, unraid confirm).

---

### 5. Statusline widget not showing in project sessions — `start.ts` fix

**Symptom:** `setupStatusline()` writes `command: "node .claude/statusline.cjs"` (relative path) to `~/.claude/settings.json`. This works when the daemon runs from `/root`, but breaks for any Claude Code session opened on a different project root (e.g. `/app`). Widget didn't appear.  
**Root cause:** `STATUSLINE_FILE` is an absolute path constant (`/root/.claude/statusline.cjs`), but the settings command used a hardcoded relative path.  
**Fix:** `src/commands/start.ts` line 225: changed `"node .claude/statusline.cjs"` → `` `node ${STATUSLINE_FILE}` ``. Settings now written with the absolute path on every daemon startup.
